# 可移植性验证：赛力斯（601127）2025 年报

> 目的：用同一套代码、**零参数调整**，跑第二家公司的年报，看判据是否成立。
> 结论先给：**解析主线可用，类型体系里的 `summary` 和三处审计假设不通用。**

## 1. 怎么跑的

| 项目 | 值 |
|---|---|
| 文件 | `raw/601127_2025_年报.pdf`，224 页，1.8 MB |
| 分批 | vlm 单文件上限 200 页 → 分 `1-200`、`201-224` 两批调 MinerU |
| 合并 | 第二批 `page_idx` 平移 +200（坑-16，目前仍是手工） |
| 重跑 | `--reuse-content-list` 复用合并结果，跑清洗 / 缝合 / 切分（不再消耗额度） |
| 产物 | `data/parsed/601127_2025_年报/`、`data/snapshots/sailis-2025-annual.json` |

两批各自的结果：第一批 200 页 261 张表、缝合 1 张；第二批 24 页 47 张表、缝合 0 张。合并后 224 页 309 个表格块。

## 3. 五条发现

### 3.1 【高】`summary` 判据不可移植

赛力斯 19 张 `summary`，**逐张看过，全是数据行的碎片**：

```
P84-P86_T84#S02   rows=2  '1.持续经营净利润(净亏损以“-”号填列)'
P149_T156#S03     rows=2  '1.期初余额'
P150_T157#S04     rows=1  '4.期末余额'
P70_T73#S02       rows=1  '不适用'
```

成因：财务附注里 `1.期初余额`、`(2)权益法下不能转损益的其他综合收益` 这类**编号子标题**被当成切分点，切出来的 1–2 行小段又满足「行数 ≤ 3 且每行非空 ≤ 4」，被判 `summary`。

比亚迪的 7 张同样不干净：`P39_T22#S02 '本科(人)'`、`P39_T22#S03 '30岁以下(人)'` 是员工学历/年龄分布表，也是 data。

**精度对照**：含「合计 / 小计 / 总额」标记的比例 —— 比亚迪 **2/7**，赛力斯 **3/19**。

**建议**：把 `summary` 的判断从「段短」改成「**段内出现合计/小计/总额行**」。这条是语义而不是统计，换公司不会失效。

### 3.2 【高】审计工具 `_parse_number` 只留 10 位有效数字

赛力斯报表单位是**元、带两位小数**（`190,501,783,194.92`），比亚迪是**千元整数**。10 位有效数字下，前者被截成 `190,501,783,200`：

```
精确值 : 190501783194.92 − 161588039865.68 = 28913743329.24002；表列净额 28913743329.24；差额 0.00002
截断后 : 190501783200 − 161588039900 = 28913743300；差额 −30        ← 误报失败
```

**这是工具 bug，不是数据问题**——四条「失败」的现金流恒等式精确值差额都在 1e-5 量级。

**建议**：`f"{value:.10g}"` 改成保留全部有效位（如 `repr(value)` 或 `.15g`），或 `_parse_number` 只返回浮点、格式化交给展示层。

### 3.3 【中】资产负债表恒等式写死了标签和表结构

赛力斯用**新准则标签** `所有者权益(或股东权益)合计`，且资产 / 负债 / 权益分在 `#S02` / `#S04` / `#S05` **三个不同段**里；检查代码要求「同一张表里同时有 `负债合计` 和 `股东权益合计`」，于是直接找不到。

数据本身是对的：`143,905,863,420.75（资产总计） = 102,047,535,793.91（负债合计） + 41,858,327,626.84（所有者权益合计）`，分毫不差。

**建议**：标签用别名集（`股东权益合计` / `所有者权益合计` / `所有者权益(或股东权益)合计`），查找范围从「同一张表」放宽到「同一组报表的全部段」。

### 3.4 【中】逻辑表碎片化

| | 1 行 | 2 行 | 合计占比 |
|---|---|---|---|
| 比亚迪 | 33 | 30 | 63/317 = 20% |
| 赛力斯 | 50 | 67 | 117/377 = **31%** |

切分把大表切成了大量 1–2 行的小段。数据不丢，但检索时这些「表」既没有表头也没有上下文。

**建议**：对切分后的段做一次合并回填——若某段 ≤2 行且父表有表头，合并回父表。这项和 3.1 是同一处代码，可以一起做。

### 3.5 【低】噪音清洗报表恒为 0

MinerU 自带 `header` / `footer` 类型，`content_list_to_pages` 已按 `_NOISE_TYPES` 直接打上 `is_noise=True`（比亚迪 543 个块、赛力斯 672 个块）。`strip_running_noise` 只统计**自己**删掉的行，所以永远报 0——**不是没清洗，是统计口径**。

但它暴露一个真问题：页眉在 `page_anchored.md` 里**仍然被渲染出来**（比亚迪 267 行「比亚迪股份有限公司 2025年年度报告全文」）。若 L0 凭证直接引用这份 MD，页眉会混进正文。

**建议**：渲染时跳过 `is_noise` 块，或单独放进 `<!-- noise -->` 注释。

## 4. 建议修复顺序

1. `_parse_number` 精度（10 分钟，改一处）
2. 资产负债表别名 + 跨段查找（30 分钟）
3. `summary` 改为「含合计/小计/总额」判定 + 小段合并回父表（半天，两处共用）
4. 噪音块不渲染（10 分钟）
5. 顺带把「200 页自动分批 + 偏移合并」做进 CLI（坑-16 仍是手工，最容易出错的一步）

前 4 项都不涉及判据调参，只是把假设写对。
