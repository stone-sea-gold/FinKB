## 1. 环境与后端选择

### 1.1 `pipeline` 后端会丢列，`vlm` 才可还原

- **现象**：同一张跨页表，`pipeline` 后端解析出来列数对不上，且**无法从输出还原**。
- **根因**：`pipeline` 遇到合并单元格时直接丢弃被合并的列；`vlm` 用 `colspan="N"`
  保留合并信息，展开后位置可还原。
- **决策**：ADR-016，默认后端锁定 `vlm`。
- **代价**：vlm 更慢更贵（未量化）。

### 1.2 vlm 单文件上限 **200 页**

- **现象**：提交 268 页被拒，报错
  `number of pages exceeds limit (200 pages), please split the file and try again`。
- **数据来源**：真实 API 报错，可信。
- **对策**：分 1-200 / 201-268 两批。

### 1.3 分批解析合并时 `page_idx` 冲突

- **现象**：268 页合并后只解析出 **200 页**，前 68 页的锚点被错映射到 201-268。
- **根因**：**每一批**的 `page_idx` 都从 0 重新编号。直接拼接 content_list 会让
  批次 2 的 `{0:201, 1:202…}` 覆盖批次 1 的 `{0:1, 1:2…}`。
- **解决**：合并时把后续批次的 `page_idx` **整体加上前序批次的最大值 + 1**，
  使其全局唯一；`page_number` 块的值保持不变（它本来就是真实物理页）。
- **待办**：此逻辑目前是**手工**做的，尚未进 CLI。

### 1.4 上传预签名 URL 时不能带任何请求头

- **现象**：HTTP 403 `SignatureDoesNotMatch`。
- **根因**：OSS 预签名校验要求 **PUT 不带任何请求头**（含 `Content-Type`）。
- **解决**：`upload_file()` 显式不传 headers。

### 1.5 MinerU 输出格式要点

- `content_list.json` 是**扁平数组**，每个元素是一个 block，字段含 `type` / `page_idx`。
- `type` 取值：`text` / `table` / `title` / `header` / `page_number` / `image` 等。
- **标题**是 `type="text"` + `text_level` 字段，**不是** `type="title"`
  （后者是 `layout.json` 的写法）。正文块**完全没有** `text_level` 这个 key。
- 表格内容在 `table_body`（HTML 字符串），可能为空（此时只有图片）。
- `page_number` 块的 `text` 就是**真实物理页码**，是页码溯源的唯一可靠来源。

## 2. 页码与锚点

### 2.1 分页解析时 `page_idx` 从 0 重编号

- **现象**：`--pages 43-44` 解析出的表，`parent_id` 是 `#P1_T02` / `#P2_T03`。
- **根因**：只解析部分页时，MinerU 返回的 `page_idx` **从 0 重新编号**。
  按 `page_idx + 1` 算物理页码，得到「第 1 页」而不是第 43 页。
- **后果**：**所有 `[Ref: doc#P1]` 锚点都会指错页**——对「物理页码强溯源」是致命错误。
- **解决**：`_build_page_number_map()` 用 `type="page_number"` 块建立
  `page_idx → 物理页码` 映射，**优先使用**；缺该块时才退回 `page_idx + 1`。
- **验证**：`test_page_number_type_overrides_renumbered_page_idx`、
  `test_page_idx_used_when_page_number_missing`

### 2.2 页码行识别要求数字等于物理页码

- **现象**：页眉剥离后，页脚单独一行的 `44` 仍残留。
- **根因**：只按「看起来像页码」判断，会把正文里的数字误删。
- **解决**：ADR-013——页码行必须满足「数字 == 该页物理页码」。
- **验证**：`test_standalone_page_number_line_is_stripped`

### 2.3 跨页表只报锚点页，页码区间恒为单页

- **现象**：`P94_T57` 有 165 行（公告索引），`page_start == page_end == 94`，
  但内容实际从 P94 铺到 P103。`P130_T77` 是现金流量表主体（45 行），一半行在 P131。
- **根因**：MinerU 遇到跨页表格时，**把所有行合并进起始页那一个 `table` 块**，
  后续每页只留一个**空的 `table` 块**（`table_body` 为空字符串）。
  那个空块带着 `page_idx` 与 `bbox`，是「表续到了这一页」的唯一证据——
  而 `content_list_to_pages` 的 `if not text.strip(): continue` 把它丢掉了。
  缝合侧再写死 `page_end=first.page`，区间就永远是单页。
- **为什么不能从 HTML 里数页数**：锚点块的 HTML 只在开头出现一次表头
  （165 个 `<tr>` 里表头 1 次），正文行不带页码。
- **为什么不能按 bbox 估**：`bbox` 是整页的框不是逐行的；折行行高不一致，
  用「页高 / 行高」估行数必然错，且错了无从核验。
- **解决**（ADR-022）：`TableBlock.page_end` + `_extend_page_end()`，
  三条护栏——① 必须已经有一张表；② 必须是**本页第一个** `table` 块
  （P65 形态：页首空块续上一页，页中实块才是新表）；③ 页码必须紧接上一张表的末页。
- **实测**：19 张表回填成功，跨页表 3 → 22 张；`parent_id` 从 `#P94_T57`
  变成 `#P94-P103_T57`；逻辑表数、类型分布、数值指纹全部不变。
- **验证**：`test_empty_table_placeholder_extends_page_end`、
  `test_empty_table_on_same_page_does_not_extend`、
  `test_empty_table_with_page_gap_does_not_extend`、
  `test_placeholder_belongs_to_the_table_above_it_on_the_same_page`、
  `test_multi_page_anchor_block_keeps_its_page_end`
- **注意**：`table_id` 仍是短表号（`#P94_T57`），带区间的叫 `parent_id`。
  报告与逻辑表号一律用 `parent_id`。

## 3. 页眉页脚与噪音

> MinerU 路径下，`type=header` / `type=page_number` 的块会被**直接打标**，无需统计推断（ADR-015）。
> 下面几条主要服务 **pypdf 兜底路径**和边缘情况。

### 3.1 跨页表头被误判成页眉清掉

- **现象**：缝合后表格没有列名。
- **根因**：跨页续接表在每页重复表头，签名频次很高，被统计判定为「运行页眉」。
- **解决**：`line_signature()` 对以 `|` 开头的行直接返回 `None`；
  `_candidate_lines()` 只考察非表格块。
- **验证**：`test_signature_rejects_table_row`、`test_repeating_table_header_is_not_stripped`

### 3.2 小文档上比例阈值退化为 1

- **现象**：只出现一次的正文行被删。
- **根因**：`int(3 * 0.3) = 0`、`int(5 * 0.3) = 1`，阈值失效。
- **解决**：`max(2, ceil(total_pages * min_ratio))`。
- **验证**：`test_single_occurrence_signature_is_not_noise`

### 3.3 单文本块页面重复计数

- **现象**：幂等性测试失败——第二次清洗又删了 3 行。
- **根因**：整页只有一个文本块时，头部行与尾部行取自同一块，同一行被计两次，阈值被虚高。
- **解决**：`_candidate_lines()` 对候选行按内容去重。
- **验证**：`test_strip_is_idempotent`

### 3.4 页眉是「文字 + 页码」时只清掉文字

- **现象**：`剥离 268 行` 看着正常，但抽查 P44 发现首块仍是 `"44\n债券 019742…"`。
- **根因**：签名只匹配文字部分，页码是另一行。
- **解决**：新增页码行识别（见 §2.2）。

### 3.5 页码作为独立块时清不掉

- **现象**：P41 页码块仍在。
- **根因**：独立页码块既不是页首块也不是页尾块，落在边缘区外。
- **解决**：增加「整块只有一个非空行」的放行条件。
- **验证**：`test_page_number_as_separate_block_is_stripped`

## 4. 块切分

### 4.1 「文本 + 表格」同块时表格消失

- **现象**：表格凭空不见。
- **根因**：整块被判为 `text`，其中的表格行被吞。
- **解决**：`_segment_block()` 按行切分成 text 段与 table 段。
- **验证**：`test_text_before_next_table_blocks_stitching`

### 4.2 无 META 的 Markdown 整篇丢失

- **现象**：解析出 0 页。
- **根因**：`flush()` 在 `current_meta is None` 时直接返回。
- **解决**：回退到 `default_doc` 第 1 页。

### 4.3 标题检测字段用错

- **现象**：`section` 继承链失效，所有标题被当正文。
- **根因**：误以为标题是 `type="title"`，实际是 `type="text"` + `text_level`。
- **解决**：`_is_heading()` 判断 `text_level is not None`。

## 5. 表格结构还原

> 这一章是最容易**静默产出错误数据**的地方，每一条都要当真。

### 5.1 MinerU 用 `<td rowspan>` 做表头，不用 `<th>`

- **现象**：P43 证券投资表明明有表头，却报 `header=无`。
- **根因**：假设「首行有 `<th>` 才是表头」。**实测 MinerU 的表头是
  `<td rowspan="2">`**，全表没有一个 `<th>`。
- **解决**：增加兼容判据——首行所有单元格 `rowspan≥2` 时也认定为表头。
- **验证**：`test_rowspan_merged_header_is_detected`

### 5.2 `rowspan` 未展开时留下全空垃圾行

- **现象**：P43 表多出一条全空行，行数比实际多 1。
- **根因**：`<td rowspan="2">` 占两行，MinerU 在第二行仍输出 1 个空 `<td>`。
- **解决**：剔除全空行，并同步维护 `row_has_th` / `row_spans` / `row_colspans` 的下标映射。
- **验证**：`test_rowspan_artifact_empty_row_is_dropped`
- **后续修正（2026-10-23）**：只剔空行不够——`rowspan` 的内容还必须**下发到被覆盖的
  行**，否则整表按列对齐时全部左移。见 5.8。

### 5.8 `rowspan` 不展开 ⇒ 第二层表头整体左移（网格化）

- **现象**：P13 首行 `['', '快报产量', '', '', '快报销量', '', '']`，第二行
  `['本报告期', '上年同期', …]` 从第 0 列开始摆，与上层分组错位一格。
- **根因**：旧实现只记录 `rowspan` 不展开，被覆盖的格子从未填进后续行。
- **解决**：抽出 `raw_rows`（原始单元格 + `rowspan`/`colspan`），用
  `_expand_merged_cells()` 统一建网格：
  - `colspan` 按列位置展开；
  - `rowspan` 用 `pending[(row, col)]` 把首格内容下发到被覆盖的每一行。
- **连带修正**：保留行的判据从「展开后是否全空」改为「**本行自有单元格是否有非空
  文本**」。占位行被进位内容填满后看起来像真实数据行，必须看自有格。
- **验证**：`test_rowspan_is_expanded_into_following_rows`、
  `test_rowspan_placeholder_row_without_own_cells_is_dropped`；
  `tools/audit.py rowspan` 可逐表对照改前/改后（年报 56 张受影响）。

### 5.9 双层表头：第二层被当成数据行

- **现象**：P29 的 `2025年/金额`、`2024年/占营业收入比重` 留在 `rows` 里；
  P262/P263/P264 更严重——第二层整行被当成「1 行数据」，`kind` 误判为 `kv`。
- **根因**：`header_offset = 1 if first_is_header else 0`，写死只吃一行表头。
- **为什么必须修**：压平后 `2025年` 与 `金额` 是两列关系，不合并成
  `2025年/金额` 就无法知道这个数字属于哪个口径；切分时也会把表头行当数据切走。
- **判据（R1/R2/R3，全部是 HTML 结构事实，不含从单份 PDF 数出来的阈值）**：
  - **R1** 当前层有 `colspan>1`，且不是「单格跨满全宽」——后者是表标题，抽成
    `table_title`，不占表头层（P66/P89 就是这种）。
  - **R2** 下一层的**自有**列 ⊆ 本层分组覆盖的列。「自有」要排除两类：
    ① 上一行 `rowspan` 下发来的列（`_carried_columns()` 复刻列游标算出）；
    ② 原地重复上一层列名的列——MinerU 对没有 `rowspan` 的 stub 列会在两层都输出
       一遍（P30 的 `行业分类`/`项目`）。
  - **R3** 下一层自有格无纯数值。
- **压平**：用 `/` 连接各层。含 `colspan` 的层要按**原始单元格列区间**取值，
  否则 `快报产量/本报告期` 会退化成 `本报告期`，分组信息整层丢失。
  **首列为空时保留空串**（见 5.7），不凭空填「项目」。
- **实测**：282 张非空物理表 → 232 张有表头 → **45 张多层表头**、5 张全宽表标题。
- **副作用（预期）**：逻辑表 324 → 320（4 张「表头单独成段」的假段并入下一段），
  `kv` 8 → 4（双层表头表原来被误判成键值表）。数值指纹逐张核对完全一致。
- **验证**：`tools/audit.py headers` 逐表列「改前表头 / 改后表头 / 原始 HTML / 勾选框」。
- **失效条件**：MinerU 自身 `colspan` 计数与内容不一致时（P128/P265 疑似），
  压平后分组列与叶子列会对不齐，这类表需人工核对。
- **别忘了往下传**：`header_rows` 必须穿过 `TableBlock → StitchedTable →
  LogicalTable` 三层。曾经只在 `TableBlock` 上算对、`StitchedTable` 没这个字段，
  结果 320 张逻辑表的 `header_rows` 全为空，多行表头只以压平字符串形式到了下游。
  **判据算对之后要用下游字段再统计一遍**（坑-26）。修复后 50 张逻辑表带多层表头、
  7 张带表标题。
- **R2 的一个真实反例（P180）**：MinerU 把 `本年变动` 的 `colspan` 少算两列、
  在行尾补了两个空 `<td>`，末两列的分组格就成了空串。原 R2 要求「所有自有列都在
  分组区间内」，这两列不在任何分组里 → 整表退化成单层表头，`本年变动/追加投资`
  的分组名全丢。**放宽为「只有父格有名字却没被分组覆盖的列才阻止判定」**。
  教训：判据里「全部满足」的写法遇到 MinerU 的残缺 HTML 就会整条失效。
- **另一条更直接的判据（未实施）**：`rowspan=2` 本身就是「这格跨两行」，
  所以 **表头层数上限 = 表头行的 max(rowspan)**。P192 的 `<td>本年增加</td>`
  没有 `colspan`（只有一个子项 `企业合并` 时 MinerU 会丢掉 colspan），
  用 R1 永远判不出来，用 rowspan 一望即知。

### 5.3 `colspan` 未展开导致数值整体左移（最危险）

- **现象**：缝合后表格「行数对、列数对」，但 P44 的数值**整体左移 2 列**。
- **根因**：`colspan="3"` 表示一格横跨三列。不展开时一个 cell 被当成一列，
  其后的所有数值整体前移。
- **危害等级**：**比缝不上更高**。缝不上会报错；错位是**静默产出错误数据**，
  一路流进 L1 事实层。
- **解决**：`_HTMLTableExtractor` 展开 `colspan`，被跨越的列补空字符串占位。
- **验证**：`test_colspan_is_expanded_to_keep_column_positions`、
  `test_stitched_rows_have_uniform_width`

### 5.4 vlm 的表头不做任何标记

- **现象**：`header=无`，表头行被当成数据行，`rows` 多 1。
- **根因**：vlm 的表头是普通 `<td>`，既无 `<th>` 也无 `rowspan`——前两条判据同时失效。
- **解决**：纯数值分布推断（ADR-012 修订版），见 §5.5 / §5.6 的三条护栏。

### 5.5 表头推断的三条护栏

判据：**首行无纯数值 + 首行 ≥2 个非空单元格 + 其后 3 行内至少一行含纯数值**。

| 护栏 | 防的错误 | 实例 |
|---|---|---|
| 首行 ≥2 个非空 | 把「全宽单格」的表标题当列名 | P89 `公司及其子公司对外担保情况`（colspan=11，1 个非空格） |
| 首行无纯数值 | 把数据行当表头 | P44 续接表首行 `债券/019742/113,357,000.00` |
| 向后探测 3 行 | 「期间表头 + 紧邻纯文本小计行」 | P137 `['', '2025年', '2024年']` 次行是 `一、经营活动产生的现金流量:` |

- **验证**：`test_period_header_detected_by_lookahead`、
  `test_fullwidth_single_cell_is_not_a_header`、`test_data_row_is_not_inferred_as_header`

### 5.6 纯文本表（整表无数字）的表头

- **现象**：P118「关键审计事项」表整表无数值，任何数值判据都失效。
- **解决**：兜底规则——**首行非空单元格全部以冒号结尾且 ≥2 个** ⇒ 表头。
- **验证**：`test_colon_terminated_first_row_is_header`

### 5.7 表头首格为空（78% 的表都是）

- **现象**：年报 229 张有表头的物理表中，**178 张（78%）`header[0] == ""`**；三季报 1/8。
- **核实**：原始 HTML 里就是 `<td></td>`。
- **结论**：**不是解析错误**——财务报表「项目」列在表头经常留空，是标准排版。
- **影响**：L1 抽取时第一列没有列名，需要兜底（按位置命名为「项目」之类）。**尚未处理**。

## 6. 跨页缝合

### 6.1 跨页续接表被当成「有表头」

- **现象**：缝合拒绝拼接。
- **根因**：走 HTML → Markdown → 再解析时，Markdown 管道表语法上必须有表头，
  强行给无表头表套了一个（ADR-012）。
- **解决**：`html_table_to_rows()` 按 `<th>`/`rowspan` 存在性返回
  `(rows, first_row_is_header, section_rows)`，保留「无表头」语义。

### 6.2 拒绝理由误导排查方向

- **现象**：P72→73 的续接表**自带表头**（`姓名/职务/报告期初持股数…`），
  却报「列数不一致（6 vs 5）」。顺着这个理由去研究「如何修列数」，
  而正确答案是「它本来就是新表，不该缝」。
- **根因**：判据把所有检查压成一个 `bool`，且**列数比较排在表头判断之前**，
  最早失败的那条成了唯一可见的理由。
- **解决**：改**三态判定**，表头检查前置。

| 结论 | 含义 | 是否告警 |
|---|---|---|
| `merge` | 确认续接 | — |
| `new` | 确认是另一张表（自带表头） | ❌ 不告警 |
| `reject` | 无法确定（无表头但列数不符） | ✅ 告警 |

- **验证**：`test_new_table_reason_is_not_column_mismatch`

### 6.3 「合计行」即表结束

- **现象**：6 条告警里 4 条（P65/P132/P214/P229）的起始表都以
  「合计」「资产总计」收尾——表明明完整，却还在尝试往后缝。
- **解决**：`stop_on_total_row`，起始表末行首列命中
  `合计/总计/小计/累计` 即静默终止，**不记告警**。
- **只检查末行**：中间的小计行不代表表结束。
- **验证**：`test_table_ending_with_total_is_not_stitched`、
  `test_total_row_only_counts_last_row`、`test_stop_on_total_row_can_be_disabled`

### 6.4 缝合的四个条件与最终结果

位置条件：① 表是**该页最后一个内容块**；② 次页第一个内容块也是表；
③ 未被消费；④ 内容判据通过（三态）。

实测结果（年报 268 页）：

| 缝合 | 位置 | 列 × 行 |
|---|---|---|
| 1 | P43→P44 | 14 |
| 2 | P58→P59 | 13 |
| 3 | **P89→P90→P91（三页链式）** | **11 × 85** |

仅 1 处告警：`P89→P92`（11 列明细表后接 2 列汇总块，**真实歧义**，应人工核对）。

### 6.5 缝不上 ≠ 错误

全量 6 处「拒绝」逐处人工核对后，**6 处全部是正确判断**：

| 边界 | 真相 |
|---|---|
| P65→66 | 起始表以「合计」结束；续接表是 2 列说明表 |
| P72→73 | 续接表**自带表头**（董监高持股表），是新表 |
| P89→92 | 11 列担保明细后接 2 列汇总块，结构不同 |
| P132→133 | 资产负债表被分页：资产段（4 列）vs 负债段（3 列） |
| P214→215 | 续接表自带表头，是新表 |
| P229→230 | 续接表首行是其新表头的一部分 |

**结论：缝合率不是目标，信噪比才是。**

## 7. 表内分节切分

### 7.1 一个物理表可以包含多个逻辑表

- **实例**：P89-P91 那个 11 列 85 行的物理表，内部实为：

| 行 | 全宽标题 | 下一行 | 语义 |
|---|---|---|---|
| r00 | 公司及其子公司对外担保情况(不包括对子公司的担保) | 11 列表头 | 数据表 ① |
| r05 | 公司对子公司的担保情况 | 11 列表头 | 数据表 ② |
| r67 | 子公司对子公司的担保情况 | 11 列表头 | 数据表 ③ |
| r78 | 公司担保总额(即前三大项的合计) | 4 格键值对 | 汇总块 |
| r82 | 其中: | 2 格键值对 | 汇总块子项 |

- **判据**：全宽行 + 后继是与已有表头相似的行 → 新数据表；后继是键值对 → 汇总块。
- **核心机制**：**切分不产生无表头的子表**——无自有表头的段继承父表表头。

### 7.2 同一语义的分节标题有两种编码

- **现象**：P137 现金流量表只识别出 1 个分节点（「三、筹资活动…」），
  漏掉「一、经营活动…」和「二、投资活动…」。
- **根因**：同一个表格里——

```html
<!-- 「一、」「二、」是 3 个普通 td，后两格空 -->
<tr><td>一、经营活动产生的现金流量:</td><td></td><td></td></tr>
<!-- 「三、」是 colspan=3 -->
<tr><td colspan="3">三、筹资活动产生的现金流量:</td></tr>
```

- **解决**：分节候选覆盖**两类**：
  1. HTML 里 `colspan` 跨满整行的全宽行（解析阶段记录在 `section_rows`）；
  2. 「仅首列非空 + 标题形态（冒号结尾或中文序号 `一、`/`（1）`/`第N章`）」的行。
- **实测**：第 2 类新增 20 处候选，**全部是真分节标题**（现金流量三段、权益变动表
  「本年增减变动金额」、大额现金流附表等），无一条误报。
- **验证**：`test_narrow_table_splits_on_numbered_heading`、`test_looks_like_heading_variants`

### 7.3 窄表上「非空单元格 ≤4」判据恒真

- **现象**：2–3 列的表里，任何一行都满足「≤4 个非空格」，汇总块判据失去区分力。
- **解决**：`summary_min_width=4`——只在 ≥4 列的表上启用该判据；
  窄表只认「冒号 / 中文序号」这类显式标题标记。
- **效果**：消除了 12 处窄表误切。

### 7.4 表头继承：切分不能丢列语义

- **现象**：P137 现金流量表切开后，三段都没有表头，`2025年/2024年` 的期间语义丢失。
- **解决**：`LogicalTable.header` + `header_source`（`self` / `inherited`）。
  无自有表头的段**继承父表表头**。
- **验证**：`test_sections_inherit_parent_header`、`test_all_sections_have_non_empty_header_when_parent_has_one`

### 7.5 单行横表 `kv_row`

- **现象**：三季报 P4_T06 首行
  `报告期末普通股股东总数 | 642,600 | 报告期末表决权恢复的优先股股东总数 | 0`
  是**一行并排两组键值对**，不是「一行数据」。
- **判据**：单元格语义交替（键=纯文本、值=含数字），两种形态：
  ① `键|值|键|值…`；② `值|键|值|键…|值`（剥离首个**孤儿值**后配对）。
  **完整配对数必须 ≥2**，非空格数 ≥4。
- **孤儿值**：P109 的首格标签在 MinerU 输出里就是空 `<td>`，导致奇数形态。
  孤儿值**不进 `rows`**，存 `orphan_values`，既不污染数据也不丢失信息。
- **验证**：`test_kv_row_key_first`、`test_kv_row_with_leading_orphan_value`、
  `test_three_cell_row_is_not_kv_row`

### 7.6 「值必含数字」的假设不成立

- **现象**：`_cell_kind` 把「尚未办完所有手续」判为**键**，而它是
  「未办妥产权证书的原因」列的**值**。P186_T134 的三个单元格
  `房屋及建筑物 | 41,744,687 | 尚未办完所有手续` **全是值**，凑出假交替。
- **根因**：财务表里大量列是**文本值**（原因/说明/状态/名称/地址/担保类型）。
- **解决**：改用**结构守卫**——**父表有表头 ⇒ 不是 `kv_row`**。
  表若有列名，每行就是「按列取值」的数据行。
- **教训**：**用结构事实判类型，不要用内容特征猜类型。**
- **验证**：`test_table_with_header_is_never_kv_row`、
  `test_same_row_without_header_is_kv_row`（同一行，仅表头有无不同）

## 8. 判定规则速查

### 8.1 表头识别（按优先级）

```
1. 首行有 <th>                                    → 表头
2. 首行所有 cell 的 rowspan≥2                      → 表头（MinerU 合并表头）
3. 首行 ≥2 非空 + 无纯数值 + 其后 3 行内有纯数值     → 表头（vlm 无标记）
4. 首行非空 cell 全部以冒号结尾且 ≥2 个            → 表头（纯文本表）
5. 首行只有 1 个非空 cell                          → 不是表头（是表标题）
```

### 8.2 跨页缝合

```
位置：本页最后一个内容块 + 次页第一个内容块，且都是表
内容：先判表头性质，再判列数
  · 有独立表头（且非重复）      → new，静默结束
  · 无表头 + 列数一致           → merge
  · 无表头 + 列数不符           → reject，记告警
前置：起始表末行是合计行        → 静默结束（表已完整）
```

### 8.3 表内分节

```
候选：colspan 全宽行 ∪（仅首列非空 + 冒号/中文序号）
分类：
  · 后继行像表头（≥3 非空、无纯数值）        → new_table（自有表头）
  · 表宽≥4 且后继非空≤4                      → summary
  · 窄表 + 标题标记                          → section_label（继承表头）
  · 以「注」开头或长度>40                    → footnote（不切分）
```

### 8.4 单行横表

```
前置：父表无表头 + 单行 + 非空格≥4
形态：键|值|键|值…            → 全部配对
      值|键|值|键…|值         → 首格孤儿 + 其余配对
约束：完整配对数 ≥2
```
