# AGENTS.md — FinKB 工作约定

本文件面向**在此目录工作的 AI agent**。开始任何任务前先读
[`DEVLOG.md`](./DEVLOG.md)。

## 开工前

1. 读 `DEVLOG.md` §1（项目是什么）、§2（当前状态）、§4（模块边界）
2. 读 §5 中与你任务相关的 ADR —— **这是设计意图，不要凭直觉推翻**
3. 读 §7（踩过的坑）—— 改相关代码前必读，否则很可能重新引入已修复的 bug
4. 读 §8（未验证项）—— **不要把推断当事实汇报**

方案层细节见 [`../FinKB-方案v2.md`](../FinKB-方案v2.md)。
**DEVLOG 是唯一权威的状态来源**；方案文档描述目标，DEVLOG 描述现实。

## 硬性约束

| 约束 | 说明 |
|---|---|
| 数字只由 SQL 计算 | 任何模块都不得让 LLM 直接产出数值（ADR-001） |
| 格式解耦 | 只有 `mineru_client.py` 允许接触外部解析格式；`noise_filter` / `table_stitcher` 不得 import 它（ADR-008） |
| 噪音块不删除 | 只打 `is_noise=True`（ADR-010） |
| 缝合用页内位置 | 不用 `block_index` 做游标 |
| 表头判定：`<th>` / 首行全 `rowspan≥2` / 纯数值分布推断 | vlm 无任何表头标记，必须靠分布推断；不得走 HTML → Markdown → 再解析（ADR-012 修订版） |
| **必须展开 `colspan`** | 不展开会让合并表数值整体左移，静默产出错误数据（坑-14） |
| 默认后端 `vlm` | vlm 用 colspan 保留合并信息可还原；pipeline 直接丢列不可逆（ADR-016） |
| 物理页码优先取 `page_number` 块 | 分页解析时 MinerU 的 `page_idx` 会从 0 重编号（坑-11） |
| MinerU 类型标签优先于统计推断 | `type=header/page_number` 直接标记噪音；统计清洗只服务 pypdf 兜底（ADR-015） |
| 清洗必须在缝合之前 | 顺序不可颠倒 |

## 完工前（强制）

**必须回写 `DEVLOG.md`**，按 §12.1 的表格执行：

- 改代码 → §11 追加变更记录
- 修 bug → §7 追加「坑-NN」（症状 / 根因 / 修复 / 测试）
- 改设计 → §5 追加或修订 ADR，**必须写失效条件**
- 放弃方案 → §6 追加一行
- 验证了未验证项 → §8 状态改 ✅ 并写验证方式
- 新依赖 / 新外部 API → §9.2 与 §8 同步

## 测试

```bash
cd finkb

```

- 全部测试必须**离线可跑**，不得依赖网络或 API key
- 修 bug 必须**先写失败测试**再修（本项目所有坑都是这样发现的）
- 测试数变化要更新 `DEVLOG.md` §2 与 §11

## 汇报纪律

- 说「已验证」时必须能指出验证方式（测试名或实测数据）
- 说「未验证」时要明说，不要用「应该」「大概」
- 外部 API 未真实联调时，必须标注「端点来自文档，未实测」
