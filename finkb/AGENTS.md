## 硬性约束

| 约束 | 说明 |
|---|---|
| 数字只由 SQL 计算 | 任何模块都不得让 LLM 直接产出数值（ADR-001） |
| 格式解耦 | 只有 `mineru_client.py` 允许接触外部解析格式；`noise_filter` / `table_stitcher` 不得 import 它（ADR-008） |
| 噪音块不删除 | 只打 `is_noise=True`（ADR-010） |
| 缝合用页内位置 | 不用 `block_index` 做游标 |
| 表头判定顺序：`<th>` → 首行全 `rowspan≥2` → 后续含数字 → 全冒号收尾 → 首格为空 | vlm 无任何表头标记，只能靠结构 + 分布推断；不得走 HTML → Markdown → 再解析（ADR-012 修订版、坑-54） |
| 多层表头用 R1–R4 判据，层数不设上限 | 层数上限是从单份文档数出来的数（坑-46）；R4 = 下层与上层同名列 ≥2 即重复打印的表头（坑-48） |
| 两列表「第二格 >12 字」是值不是列名 | 否则「统一社会信用代码 / 9150…」这种键值对会被当表头（坑-54） |
| **必须展开 `colspan`** | 不展开会让合并表数值整体左移，静默产出错误数据（坑-14） |
| 默认后端 `vlm` | vlm 用 colspan 保留合并信息可还原；pipeline 直接丢列不可逆（ADR-016） |
| 物理页码优先取 `page_number` 块 | 分页解析时 MinerU 的 `page_idx` 会从 0 重编号（坑-11） |
| MinerU 类型标签优先于统计推断 | `type=header/page_number` 直接标记噪音；统计清洗只服务 pypdf 兜底（ADR-015） |
| 清洗必须在缝合之前 | 顺序不可颠倒 |
| 缝合判据先判表头、再判列数 | 顺序颠倒会让「新表」被误报成「列数不符」（坑-17） |
| 合计行即表结束，且不告警 | 正常情况不该制造告警噪声（坑-18 / ADR-017） |
| **切分不得产生无表头的子表** | 无自有表头的段必须继承父表表头（ADR-018）；否则期间/列语义丢失 |
| 表头识别看**后续任意行**有无数值，不设探测窗口 | 窗口是从单份文档数出来的数，会随排版失效（坑-42） |
| 全宽单格不得判为表头 | 那是表标题，不是列名（ADR-019） |
| 分节候选要覆盖两种编码 | MinerU 对同一标题可能用 colspan，也可能用普通空单元格（坑-20） |
| 单行横表要按键值对解析，不能按列取值 | 一行可含多组键值对（ADR-020）；且必须 ≥2 组配对，否则会误判普通数据行（坑-21） |
| 孤儿值不进 rows | 存 `orphan_values`，既不污染数据也不丢失信息 |
| 一行四格「键、值、键、值」不算表头 | 偶数格 + 键不带数字 + 值带数字 + 无年份格，四条同时成立才是键值行（坑-56） |
| **父表有表头 ⇒ 不是 `kv_row`** | 用结构事实判类型；「值必含数字」的假设不成立（坑-22） |

## 完工前（强制）

**必须回写 `DEVLOG.md`**，按 §12.1 的表格执行：

- 改代码 → §11 追加变更记录
- 修 bug → §7 追加「坑-NN」（症状 / 根因 / 修复 / 测试）
- 改设计 → §5 追加或修订 ADR，**必须写失效条件**
- 放弃方案 → §6 追加一行
- 验证了未验证项 → §8 状态改 ✅ 并写验证方式
- 新依赖 / 新外部 API → §9.2 与 §8 同步
