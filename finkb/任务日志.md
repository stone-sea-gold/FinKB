### T-17 多行表头（网格化 + R1/R2/R3 + 压平）
- **动因**：`kv` 判据 8 张错 7 张，追根是「双层表头」。中国年报财务表大量用
  `2025年/金额`、`本年变动/追加投资` 这种两层列名，系统却写死 `header_offset = 1`，
  第二层整行被当成数据行；叠加 `rowspan` 未展开，第二层还整体左移一列
- **两步走**（用户批准：先网格化，再多行表头）：
  - **步1 网格化**（提交 `ca3a1a2`）：`_HTMLTableExtractor` 只产出 `raw_rows`，
    `_expand_merged_cells()` 统一建网格（`colspan` 按列位置展开、`rowspan` 用
    `pending` 把内容下发到被覆盖行）；保留行改按「本行自有单元格」判断
  - **步2 多行表头**：`html_table_layout()` 新 API；R1（有 `colspan>1` 且非全宽标题）
    + R2（下层自有列 ⊆ 上层分组列）+ R3（下层无纯数值）；`_carried_columns()` 排除
    rowspan 下发列，并排除「原地重复上层列名」的 stub 列；压平用 `/` 连接
- **判据全部是 HTML 结构事实**，没有引入任何「从这份 PDF 数出来的」新阈值
- **实测**：多层表头 **45 张**；全宽表标题抽出 **5 张**；逻辑表 324 → **320**
  （4 张「表头单独成段」的假段并入下一段）；`kv` 8 → **4**
- **核验**：`tools/audit.py headers` 逐表列「改前表头 / 改后表头 / 原始 HTML / 勾选框」；
  `diff` 61 张变化全部落在表头与行数；14 条守恒律全过（含三张现金流量表）
- **踩到的坑**：R2 最初用原始单元格判断，P29 的 `同比增减` 是 rowspan 下发的、
  P30 的 `行业分类`/`项目` 是 stub 列重复输出，都会被误判——补 `_carried_columns`
  与「原地重复」两条排除后，45 张全部正确
- **验证**：174 passed（127 + 42 + 2 新增 + 3 步1）；`--reuse-content-list` 重跑年报
  确认 320 张、继承表头 263 张

### T-18 跨页表页码区间（空 table 占位块回填 `page_end`）
- **动因**：`P94_T57` 有 165 行，`page_start == page_end == 94`，实际覆盖 P94–P103。
  引用「第 X 页」的 L0 凭证全部失真，共 **19 张跨页表、29 张逻辑表、638 行**
- **根因**：MinerU 把跨页表合并进起始页那个块，后续页各留一个**空 table 占位块**；
  `content_list_to_pages` 的 `if not text.strip(): continue` 把空块直接丢了，
  缝合侧 `page_end=first.page` 又把起止都写成锚点页
- **为什么不选别的方案**：锚点块 HTML 不在每页重复表头（数不出页数）；按 bbox
  高度除行高估行数必然错；逐行页码归属的 PDF 反查只有 57% 覆盖率，
  剩下 43% 静默出错比给一个诚实区间更危险
- **实施**（提交见下）：`TableBlock.page_end` + `last_page` 属性；
  `_extend_page_end()` 三条护栏（已有表 / 本页第一个 table 块 / 页码连续）；
  缝合改用 `first.last_page` 与 `next_block.table.last_page`
- **用户决定**：「选A，表格仍只渲染一次（在 P94）」——`page_anchored.md` 不重复渲染，
  区间信息由 `page_end` 携带
- **实测**：跨页物理表 3 → **22 张**；逻辑表仍 320、类型分布不变、
  `parent_id` 变为 `#P94-P103_T57`；14 条守恒律全过
- **核验**：`tools/audit.py page-spans` 生成 `data/reports/fix-page-span-年报.md`，
  逐张列「占位块页 + PDF 文本反查 + 三条勾选项」；21/22 张有行能在区间内定位
- **顺带修**：`audit.py diff` 增加「改号」配对——表号从 `#P94_T57` 变 `#P94-P103_T57`
  时 kind/行数/数值指纹全变，不配对会被读成「29 张表消失了」。配对键抹平页码段但
  **保留 `_T{seq}`**，否则内容相同的合并表/母公司表会被误配
- **验证**：179 → **187 passed**（+4 占位块回填、+1 缝合、+5 审计证据/改号配对）
- **顺带修掉一个隐藏断链**：`StitchedTable` 缺 `header_rows` / `table_title`，
  `split_sections.emit()` 主路径又不传，导致 320 张逻辑表的 `header_rows` **全是空**——
  多行表头只以压平字符串的形式到了下游。补字段 + 缝合透传 + `emit()` 透传后，
  **50 张逻辑表**带多层表头原貌、**7 张**带表标题；188 passed
