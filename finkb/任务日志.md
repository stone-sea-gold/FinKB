## 3. 任务流水

按时间顺序。每条含：做了什么、关键决策、验证方式、对应提交。

### T-01 项目骨架与 IR 建模
- 建立 `DocMeta` / `Block`（含 `is_noise`）/ `TableBlock` / `StitchedTable` / `StitchResult`
- 定下「格式解耦」：只有 `mineru_client.py` 能碰外部解析格式（ADR-008）
- **验证**：单元测试覆盖模型与渲染

### T-02 页码锚定 Markdown 解析
- 解析 `<!-- META: {...} -->` 段，切分块；`_segment_block` 处理「文本+表格」同块
- **验证**：`test_text_before_next_table_blocks_stitching`

### T-03 噪音清洗（统计签名）
- 页眉页脚靠「行签名 + 出现页数比例」识别，噪音**打标不删除**（ADR-010）
- 修掉坑-01～05（见 PDF 解析细节 §4）
- **验证**：pypdf 路径 268 页剥离 534 行，签名命中 268/268

### T-04 跨页表格缝合
- 四条件判定（页末表格 + 次页页首表格 + 列数 + 表头性质）
- 支持三页链式、重复表头、拒绝审计
- **验证**：15 项缝合测试（构造数据）

### T-05 MinerU 客户端
- 三条链路：预签名 URL 上传、URL 直传、pypdf 离线兜底
- 轮询 + 分页解析
- **验证**：`test_page_number_type_overrides_renumbered_page_idx` 等

### T-06 content_list 适配层
- `content_list_to_pages()` 把 MinerU block 转成 IR
- 坑-08：标题判定用 `text_level is not None`，不是 `type == "title"`
- **验证**：真实 content_list 跑通

### T-07 首次真实联调（pipeline 后端，P43-44）
- 提交 `29605b7`
- 发现三处与文档不符：页码重编号、`<td rowspan>` 表头、rowspan 空行
- **验证**：真实 API 调用，产出 `content_list.json`

### T-08 切 vlm 后端 + colspan 展开 + 表头推断
- 提交 `0618f94`
- 发现 pipeline 后端**丢列不可逆**，vlm 用 `colspan` 保留合并信息 → 定 vlm 为默认（ADR-016）
- colspan 展开、纯数值分布推断表头
- **验证**：P43-P44 缝合为 14 列 × 14 行，列位正确

### T-09 全量 268 页解析
- 提交 `ea78326`
- vlm 单文件上限 **200 页**（实测），分 1-200 / 201-268 两批
- 坑-16：两批 `page_idx` 都从 0 开始，合并后 268 页塌成 200 页 → 手工偏移合并
- **验证**：278 张逻辑表，3 张跨页缝合（含 P89-P91 85 行三页链式）

### T-10 缝合判据修订（P0 + P1）
- 提交 `f9f3d7b`
- 逐处核对全量跑出的 6 处告警，结论：**6 处拒绝全部正确**，问题在报告方式
- P0：二态 → 三态（`merge` / `new` / `reject`），表头检查前置（坑-17）
- P1：`stop_on_total_row`，合计行即表结束且**不告警**（坑-18）
- **结果**：告警 6 → 1，缝合数不变（3 张）
- **验证**：`test_new_table_reason_is_not_column_mismatch` 等 7 项新测试

### T-11 两级表格模型（物理表 → 逻辑表）
- 提交 `32f313e`
- 背景：P89-P91 一个 11 列 85 行的物理表内部实为 **3 张数据表 + 2 个汇总块**
- 新增 `LogicalTable`（`header` / `header_source` / `section_path` / `kind`）
- **核心机制：表头继承**——切分不产生无表头的子表（ADR-018）
- 步骤 0：修表头识别（期间表头 + 冒号列名 + 全宽单格护栏，ADR-019）
- 步骤 2：`section_splitter.py`，分节候选覆盖 MinerU 的两种编码（坑-20）
- **结果**：278 → 324 逻辑表，262 段继承到非空表头
- **验证**：P137 现金流量表切 3 段，每段保留 `2025年/2024年`

### T-12 单行横表 `kv_row`
- 提交 `183c78e`
- 背景：三季报 P4_T06 首行是「键|值|键|值」，一行并排两组键值对
- 新增 `kind="kv_row"` + `pairs` / `orphan_values` 字段
- 孤儿值（首格标签丢失）不进 `rows`，存 `orphan_values`
- **验证**：年报 P109（3 对 + 1 孤儿）、三季报 P4_T06（2 对）

### T-13 kv_row 判据改用结构守卫
- 提交 `ca69de1`
- 坑-22：`_cell_kind` 假设「值必含数字」，文本值列（原因/说明）会被误判为键
- 修复：**父表有表头 ⇒ 不是 kv_row**（结构事实，不依赖内容猜测）
- **验证**：`test_table_with_header_is_never_kv_row` + `test_same_row_without_header_is_kv_row`

### T-14 三季报解析与审核报告工具
- 三季报 10 页 → 9 物理表 → 18 逻辑表
- `tools/section_split_review.py`：**直接调用生产 `split_sections`**，不另写判据
- 产物：`data/reports/section-split-review-年报.md`、`-三季报.md`
- **验证**：人工逐表核对

