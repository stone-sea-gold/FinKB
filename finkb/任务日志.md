### T-27 数值回查与页码偏移修复

- **动因**：既有核验全建立在自己解析的数据上，无法证明「单元格没解析错、页码没错」
- **做法**：`tools/audit.py verify-cells` 把每个逻辑表的数字回查到 PDF 原文（≥6 位数字才抽，避免年份噪声），并顺带做 ±1 页偏移自检
- **查出**：长安半年报 24%，整体右移一页后 100% → 页码系统性早一页
- **根因**：页脚数字被当成物理页码；该文档有封面页
- **修法**：`page_number` 映射改为只在 `--pages` 时启用；整份解析用 `page_idx + 1`；新增 `detect_page_offset()` 兜底
- **验证**：三份文档 `verify-cells` 100%/99%/100%，逻辑表数一张未变，守恒律 14/11/11，257 项测试

  缝上了，说明 `merge_batches` 的偏移是对的

### T-32 原文召回：证明 MinerU 没有整表丢弃

- **动机**：`verify-cells` 只证明「我们的数字在原文里」（精确率）。若 MinerU 整张表丢了，
  精确率仍是 100%。缺一个反向指标。
- **做法**：`tools/audit.py recall --doc --pdf`。数字去千分位后做**子串**比对（对「抽取把数字
  拆行 / 粘串」两种失真免疫），表按 `page_start..page_end` 覆盖页归属。
- **结果**：18 份 **19782 个数字，页内对上 98%，加上他页找到共 19577 个**；剩 205 个逐个看
  上下文，**全部是 PDF 文本层粘连**（页脚 `86` 与 `9,638,215.61` 粘成 `869638215.61`、
  图表坐标轴、公告编号与年份粘连），无一是表格数据。
- **结论**：原文数字召回实为 **100%**，MinerU 没有整表丢弃。报告 `data/reports/recall-18docs.md`。
- **顺带发现（未处理）**：39 张表的表头中间有空洞（有数据但那一列没名字），集中在季报/半年报的
  股东信息表——MinerU 把两行表头拆成「表头行 + 数据行」，只认了第一行。

- **判据**：回溯时跳过噪音/空块/期间标签/单位与抬头行/目录行/复选框行；遇表格 →
  adjacent_table；遇标题 → heading；遇长正文 → missing；短句按冒号或提示词分
  self / text。**没有新增任何数量阈值**，唯一的数字是「正文超过 80 字」。
- **实测**：比亚迪 `61 / 25 / 196 / 28 / 7`，赛力斯 `34 / 59 / 257 / 21 / 6`；

- **核验产物**：`data/reports/caption-map.md`（两家 694 张全量，`text` 与 `missing`

- **为什么不在 layout 阶段删**：会让分片宽度变化，导致缝合判据结果漂移（两个测试同时红）
- **结果**：含空列的表 **50 → 34**、空列 **213 → 99**；逻辑表 4039、有表头 3804（94.2%）、裸表 235 全不变；22 份守恒律全过；**287 tests**

## T-45 语料基线：把「有没有变差」变成可判定的

- **动因**：`corpus` 报告的是**状态**不是**变化**，改坏了也看得到一张漂亮的表
- **做法**：`audit baseline` 写 `config/corpus-baseline.json`（22 份 × 5 个数字，约 3KB，进 git）；`corpus --baseline` 只报变差的三件事——有表头张数减少、守恒律通过数减少、文档消失
- **验证**：伪造一次退步（某份 header +3）→ 退出码 4 并打印「18 → 15（退步 3 张）」；真实语料对照零退步退出码 0；291 tests
- **接进验收**：`scripts/check.sh` 改成 `corpus --baseline config/corpus-baseline.json`
